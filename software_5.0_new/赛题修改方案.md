## 二、游客交互侧 — 差距与修改方案

### 2.1 多模态交互（功能完整度 + 技术创新性，影响约15分）

#### 现状

- **已实现**：文本输入对话、TTS语音播报（edge-tts 晓晓）、3D数字人模型加载（three-vrm）、流式SSE响应
- **已实现（AR模块）**：摄像头实时画面识别、AR交互问答、AR虚实叠加卡片

#### 缺失项

| 缺失项 | 严重度 | 赛题要求原文 |
|--------|--------|-------------|
| 语音输入（ASR） | 高 | "支持语音输入和文本输入" |
| 口型同步 | 高 | "以口型同步的方式进行回答" |
| 表情动画 | 高 | "以表情的方式进行回答" |
| 情感互动 | 中 | "情感互动" |

#### 修改方案

**① 语音输入（ASR）**

- 在 `chat.vue` 中集成 Web Speech API（`webkitSpeechRecognition`）实现浏览器原生语音识别
- 后端 `server.py` 新增 `/api/asr` 接口，使用 Whisper API 作为备选方案（弱网/不兼容时降级）
- 交互设计：语音按钮长按录音，松开自动转文字并发送；录音中显示波形动画
- 移动端兼容：iOS Safari 14+ 支持，Android Chrome 支持

**② 口型同步**

- `Avatar3D.vue` 中新增口型驱动逻辑，两种方案并行：
  - **方案1（推荐，通用）**：基于TTS音频的 `AudioContext` 频域分析，提取音量振幅，驱动下颌骨（Jaw bone）旋转模拟开合
  - **方案2（需BlendShape）**：基于AI回答文本的音素分析，映射到视素（viseme）形变，驱动BlendShape
- 由于 `secondone.vrm` 无 BlendShape，使用骨骼驱动方案：通过旋转 `jaw` 骨骼模拟开合嘴
- 对 `guide.vrm`（9.5MB，可能含BlendShape）则优先使用 BlendShape 驱动
- 实现要点：TTS播放时实时分析音频频谱 → 计算振幅值 → 映射到下颌骨旋转角度（0~15度）

**③ 表情动画**

- 在 `aiResponder-doubao.ts` 中新增情感检测逻辑：分析AI回答文本的情感倾向（积极/中性/消极）
- `Avatar3D.vue` 中根据情感映射到预设表情：
  - 积极情感 → 微笑（通过骨骼旋转或 BlendShape `joy`）
  - 中性情感 → 默认表情
  - 消极情感 → 同情表情
- 如果模型无 BlendShape，通过控制眉骨和嘴角骨骼模拟表情
- 表情切换使用缓动插值（lerp），过渡时间0.3秒，避免生硬跳变

**④ 情感互动**

- 在 AI prompt 中加入情感指令：`"请根据游客的问题情感，在回答开头添加[情感标签]，如[微笑]、[严肃]"`
- 前端解析情感标签，驱动数字人表情和TTS语速/语调变化
- 记录游客情感数据到后端数据库，供管理端生成情感趋势报告

### 2.2 智能问答与讲解（功能完整度 + 技术创新性，影响约12分）

#### 现状

- **已实现**：GLM-4-Flash 文本对话、GLM-4V-Flash 多模态视觉识别、景点数据（spots.ts 含14个景点完整信息）、问答库（qa-bank.ts）
- **已实现（AR模块）**：AR场景识别 + 知识库联动问答

#### 缺失项

| 缺失项 | 严重度 | 说明 |
|--------|--------|------|
| 知识库RAG增强 | 高 | AI回答未与本地知识库关联，可能产生幻觉 |
| 准确率保障 | 高 | 赛题要求"事实性问答准确率不低于90%" |
| 多轮对话上下文 | 中 | chat store 缺少上下文管理，多轮对话会丢失语境 |

#### 修改方案

**① 知识库RAG增强**

- 后端 `server.py` 的 `/api/chat` 接口中，在调用 GLM 之前，先从本地知识库（qa-bank.ts + spots.ts + 管理员上传的知识）中检索相关内容
- 检索策略：
  - 关键词匹配：提取游客问题中的景点名、关键词，匹配知识库条目
  - 景点ID匹配：AR识别到景点时，直接拉取该景点完整知识
- 将匹配到的知识作为 system prompt 注入：
  ```
  你是灵山胜境的AI导游小乐。请基于以下知识库内容回答游客问题：
  {知识库内容}
  如果知识库中没有相关信息，请诚实告知并建议游客咨询景区工作人员。
  ```
- 这能确保 AI 回答基于本地知识库，准确率达到90%+

**② 多轮对话上下文**

- `chat store` 中维护最近5轮对话历史
- 每次请求将历史对话一并发送给 GLM，实现上下文连续对话
- 超过上下文长度时，保留最近5轮 + 系统提示，旧对话自动截断

### 2.3 个性化推荐（功能完整度，影响约5分）

#### 现状

- **已实现**：`routes.vue` 有预设游览路线展示
- **缺失**：无基于游客兴趣的个性化推荐

#### 修改方案

- 在 `chat.vue` 或 `index.vue` 新增"兴趣标签"选择入口：
  - 历史文化 / 自然风光 / 佛教艺术 / 美食体验 / 亲子游览
- 游客选择兴趣后，AI 对话的 system prompt 中加入兴趣信息：
  `"游客对{兴趣}感兴趣，请在回答中侧重相关内容。"`
- `routes.vue` 根据兴趣标签过滤和排序游览路线：
  - 历史文化 → 优先展示祥符禅寺、阿育王柱路线
  - 自然风光 → 优先展示放生池、九龙灌浴路线
  - 佛教艺术 → 优先展示梵宫、五印坛城路线
  - 美食体验 → 优先展示周边美食推荐路线
  - 亲子游览 → 优先展示百子戏弥勒、九龙灌浴路线
- 在 AI 对话过程中，根据游客提问关键词动态更新兴趣画像

### 3.3 游客感受度报告（功能完整度 + 技术创新性，影响约8分）

#### 现状

- **已实现**：`report.vue` 有基础报告展示
- **缺失**：情感分析、关注点分析、服务建议生成

#### 修改方案

**① 情感分析**

- 后端 `server.py` 新增 `/api/admin/sentiment-analysis` 接口
- 使用 GLM-4-Flash 对游客对话记录进行批量情感分析
- 输出每位游客的情感评分（-1到1）和情感标签（满意/困惑/不满/兴奋）
- 生成情感趋势图（按时间/景点维度）
- 识别负面情绪高发场景，预警服务风险

**② 关注点分析**

- 提取游客提问的高频关键词，生成词云可视化
- 按景点统计关注热度（哪些景点被问得最多）
- 按问题类型分类统计（历史类/路线类/票价类/设施类）
- 识别"知识库未覆盖"的高频问题，提示管理员补充知识库

**③ 服务建议**

- 基于情感分析结果，AI自动生成改进建议
- 例如："游客对梵宫的关注度最高但满意度偏低，建议增加梵宫讲解内容"
- 按优先级排序建议（高影响+低满意度 > 其他）

### 4.3 口型同步与自然度（技术创新性，影响约5分）

#### 修改方案

- **优先使用 `guide.vrm`**（9.5MB，可能有BlendShape）而非 `secondone.vrm`（85MB，无BlendShape，加载慢）
- 如果 `guide.vrm` 有 BlendShape，直接驱动口型 BlendShape（`aa`、`ih`、`ou`、`ee`、`oh`等视素）

- 语音合成：edge-tts 晓晓音色已达标，确保语速和情感匹配
- 数字人待机动画：添加呼吸起伏微动画和随机眨眼，提升自然度

### 4.4 响应延迟控制（行业实用性，影响约3分）

#### 现状

- 流式SSE响应已实现，首字延迟通常<2秒

#### 修改方案

- 确保 TTS 与文本流式并行：边生成文本边分段合成语音
- 知识库检索使用内存缓存，避免每次查询数据库
- 移动端图片懒加载和CDN优化

## 七、技术选型建议

| 需求 | 推荐方案 | 备选方案 | 理由 |
|------|----------|----------|------|
| 语音识别(ASR) | Web Speech API（浏览器原生） | Whisper API / 讯飞ASR | 零成本，移动端兼容性好 |
| 口型同步 | AudioContext频谱分析 + 骨骼旋转 | viseme映射 + BlendShape | 通用性强，不依赖BlendShape |
| 表情动画 | 情感标签 + 骨骼旋转模拟 | VRM BlendShape | 适配无BlendShape的模型 |
| 知识库RAG | 关键词检索 + system prompt注入 | 向量数据库 + 语义检索 | 实现简单，准确率高 |
| 情感分析 | GLM-4-Flash批量分析 | 专业情感分析API | 复用现有模型，无额外成本 |
| 数据可视化 | ECharts | uCharts / AntV | 功能强大，文档完善 |
| TTS语音合成 | edge-tts 晓晓 | 讯飞TTS | 已集成，免费，音质好 |

## 八、创新要点总结（用于PPT和文档）

1. **AR实景识别导览**：通过摄像头实时识别景区景点，虚实叠加信息卡片，行业首创的AR+AI导游体验
2. **多模型统一调度**：管理员可配置多款AI模型（GLM/DeepSeek/Qwen/MiniMax），用户侧自由切换，自动容错降级
3. **知识库RAG增强**：本地知识库 + 大模型，确保事实性问答准确率90%+，避免AI幻觉
4. **多模态情感互动**：语音输入 + 口型同步 + 表情动画 + 情感分析，全链路多模态交互
5. **大字版无障碍设计**：内置大字模式和英文国际化，服务老年游客和外国游客
6. **A*智能导航**：景区路网A*算法寻路，支持最短路径/景观优先/无障碍三种模式
7. **完整管理后台**：知识库管理 + 数字人配置 + 游客情感分析 + 数据大屏，一站式运营管理
8. **设备自适应AR**：根据设备性能自动调整AR渲染参数，低端设备也能流畅运行
